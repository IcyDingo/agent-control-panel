# Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Settings dialog for every workspace and for Glue itself. It replaces the first-run checklist, the bell
and the Answering switch, and keeps its seal exceptions inside the dialog.

**Architecture:** Glue-wide prefs move into a small module (`glue-prefs.mjs`) and are stored as `prefs.json` → `glue`.
The server gains two Settings-only routes:
- `GET /api/settings` carries the seal exceptions: all workspaces' identity and status, and the full repository map.
- `GET /api/glue` carries the non-sensitive Glue prefs every page needs.

A content-free `settings` SSE event tells pages to refetch. The relaxed workspace routes (rename, reorder, connect,
sign-in, repository moves) act on any workspace. The page builds a `<dialog id="settings">` with five tabs and removes
the overseer-page checklist.

**Tech Stack:** Node 20+ ES modules with no dependencies, `node:test`; the single-file page `public/index.html`; Swift
`app/main.swift` for one menu item.

**Spec:** `docs/superpowers/specs/2026-11-13-settings-design.md` (it builds on
`docs/superpowers/specs/2026-11-13-workspaces-design.md`).

## Global Constraints

- **Exceptions stay inside Settings.** Data about a workspace other than the page's focus, beyond
  `{ id, name, color, waiting }`, reaches the page **only** through `GET /api/settings`. That data is exactly:
  - per workspace: `id`, `name`, `color`, `order`, `signedIn` (true, false or null), `connected`, `loginCommand`,
    `here`;
  - per repository: `key`, `label`, `ws`, `stored`;
  - the account email and plan for the focused workspace only.
- **Never sent** for another workspace, anywhere (Settings included): account email, sessions, PR titles, branches,
  conversations, feed.
- **Nothing from `/api/settings` goes into an SSE frame.** The `settings` SSE event's data is exactly `{}`.
- The board, GitHub panel, overseer, notifications, title and badge stay as sealed as before.
- **Answering here** is never persisted. The server starts with it on.
- With exactly one workspace, Settings shows one workspace row with no order controls, and nothing else changes from
  today's look except that ⚙ replaces Setup, the bell and the switch.
- Server-side files stay `0600`. Unknown keys in `prefs.json` are kept on write (as `savePrefs` does today).
- Copy, verbatim from the spec:
  - the tour stop reads `Settings: logins, workspaces, answering, alerts`;
  - provider rows read `Coming next: run agents with OpenAI's Codex` and `Coming next: any model, through your
    OpenRouter key`;
  - the top bar notice reads `Paused: the terminal answers everything`.

## Review Focus

1. **Two pages.** A rename in one page while the other has Settings open: expect the open dialog to refetch. Pinned
   in Task 2: every mutating Settings route emits a `settings` event, with data `{}`, to every client.
2. **Restart from Settings while paused.** Expect Answering back on after the restart. Pinned in Task 3.
3. **A missing, corrupt or partial `glue` in `prefs.json`.** Expect the defaults, no crash, and other prefs keys
   untouched. Pinned in Task 1.
4. **Forget on a repository known only from a session.** Expect `stored:false`, no Forget offered, and the route a
   harmless no-op. Pinned in Task 2.
5. **Connect for the workspace you're not in.** Expect that workspace's `settings.json` changed and the focused one's
   untouched. Pinned in Task 2.

**Interfaces:**
- Produces:
  - `GLUE_DEFAULTS`: `{ theme: 'dark', folded: ['idle','finished'], notify: { requests: true, ci: true, watcher: true },
    titleCount: true, agentDefaults: { model: '', effort: '', mode: 'default', worktree: false }, overseerModel:

    strings, each at most 100 characters.

    patch containing an unknown field or a bad value, naming the field in `error`.
  - `store.reorder(ids: string[]): { ok, error? }`. Its `ids` must be a permutation of the current workspace ids.

- Produces:
  - `glue()`: the current sanitized Glue prefs.
  - `settingsChanged()`: sends the SSE event `settings` with data `{}` to every client.
  - `GET /api/glue` returns `{ ok, glue }`.
  - `POST /api/glue/seed { theme, folded }` is accepted only while `glue.seeded === false`, and sets
    `seeded: true`.
  - `POST /api/settings/glue { patch }` returns `{ ok, glue }` or `{ ok:false, error }`.
  - `GET /api/settings` returns `{ ok, workspaces, repos, glue, github: { state, login }, watcher: { enabled },
    overseer: { model, models }, about }`:
    - `workspaces` items: `{ id, name, color, order, here, signedIn, connected, loginCommand, account? }`, where
      `account` is present only when `here`;
    - `repos` items: `{ key, label, ws, stored }`. The set is the union of stored assignments, repositories live
      sessions work in, and repositories the GitHub poller watches. `stored` is true only for keys in
      `workspaces.json`.

  - Relaxed routes. Each still refuses an unknown id with `No such workspace.`.
    - `POST /api/workspace/update { id, ... }` accepts any id.
    - `POST /api/profile/connect { id }` accepts any id.
    - `POST /api/setup/login { what, ws? }` signs in `ws`, or the focus when `ws` is absent.
  - New routes:
    - `POST /api/workspace/reorder { ids }`;
    - `POST /api/settings/assign { key, ws: string[] }`, which calls `store.assign(key, ws)` with no
      focus rules. It validates the key shape and the ids, and for `ws: []` on a key that isn't stored it returns
      `{ ok: true }` and changes nothing.
  - Every mutating route above, a finished sign-in check (`checkSetup` changing a status), and a workspace appearing or
    going call `settingsChanged()`. The page route `/api/workspace/assign` keeps its existing rules.
