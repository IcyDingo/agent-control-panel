# Issues: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Issues panel on the right (its own top-bar button, its own container, stacked with GitHub's when both are open), where each issue's items can be picked up by an agent, and show to do / being worked on / done.

**Architecture:** A store module `issues.mjs` (per workspace, its own JSON file in Glue's data folder) holds issues and items. A space gets a `goal` in `workspaces.mjs`. The server adds `/api/issue/*` routes, links a launched agent to its item by launch id, records the branches the agent works on, and marks an item done when a PR from one of those branches merges (`github.mjs` keeps following those branches). The page draws the panel with `el()`/`patch()`; what an item shows is decided in `public/home-board.js` (`itemView`).

**Tech Stack:** Node standard library, `git`/`gh` as already used, one-file page, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-25-issues-design.md` (and the Goals part of `docs/superpowers/specs/2026-11-24-home-overview-design.md`)

## Global Constraints
- Issue title ≤ 120 characters, item text ≤ 300, space goal ≤ 120; one line each (newlines become spaces).
- Every pick-up runs in a worktree of its own, named `issue-<item id>` (8 hex), whatever Settings says.
- The prompt an agent gets: the item's text, a blank line, then `This is part of: <issue title>.`
- Done = a merged PR from a branch recorded on the item, or the owner's tick. Never guessed.
- A space the issue made follows the issue's renames (name and goal); a linked space is never renamed by it; linking sets the goal only when the space has none; renaming a space never renames the issue.
- Per workspace only: nothing of one workspace's issues reaches another's page.
- Nothing is sent to GitHub beyond what the poller already does, plus following recorded branches.

## Review Focus
1. Two pick-ups at once on one issue's first pick-up must not make two spaces.
2. An item whose agent is cleared from the board before its PR merges still becomes done (the poller keeps following its branches).
3. Deleting an issue's space unlinks the issue; the next pick-up makes a new space.
4. A reorder drag that drops on itself, or onto another issue, must not lose or duplicate an item.
5. Typing a new item, then a snapshot redraw arrives: the half-typed text must survive.

### Task 1: The issues store and a space's goal

**Files:** Create `issues.mjs`, `test/issues.test.mjs`. Modify `workspaces.mjs` (goal on a space), `test/workspaces.test.mjs`.

**Interfaces — Produces:**
- `createIssues({ file })` → store with: `list(ws)` → issues (copies), `create(ws, title)` → `{ ok, id }`, `rename(ws, id, title)`, `remove(ws, id)`, `addItem(ws, issue, text)` → `{ ok, id }`, `editItem(ws, issue, item, text)`, `removeItem(ws, issue, item)`, `move(ws, { issue, item?, before? })` (an item to before another item id or the end of its issue; or an issue before another issue id or the end), `tick(ws, issue, item, on)`, `back(ws, issue, item)` (to do, session cleared), `setSpace(ws, issue, space, owns)`, `unlinkSpace(ws, space)` (every issue with that space), `setLaunch(ws, issue, { folder, choices })`, `startItem(ws, issue, item, launchId)`, `claimItem(ws, launchId, sessionId)` → `{ ws, issue, item } | null`, `addBranch(ws, issue, item, branch)`, `done(ws, issue, item, pr)`, `openItems()` → `[{ ws, issue, item, sessionId, launchId, branches, folder }]` for items not done. Every write saves the file (0600). A bad saved file is dropped item by item, as the spaces store does.

- `workspaces.mjs`: `createSpace(ws, name, goal?)`, `setGoal(ws, id, goal)`, `spacesOf` includes `goal` (''), goal kept across a restart.

### Task 2: Server routes, pick-up, linking, done by merge

**Files:** Modify `server.mjs`, `github.mjs` (`mergedOf(slug)`; follow extra branches), `test/issues-server.test.mjs` (new, end to end with a stand-in `claude` and `gh`, in the style of `test/agent-api.test.mjs`).

**Interfaces — Consumes:** Task 1's store. **Produces:** routes (all page routes, token and workspace seal as the others): `/api/issue/create {title}`, `/rename {id,title}`, `/delete {id}`, `/item/add {issue,text}`, `/item/edit {issue,item,text}`, `/item/delete {issue,item}`, `/move {issue,item?,before?}`, `/tick {issue,item,on}`, `/back {issue,item}`, `/link {issue,space}`, `/prepare {issue}` → `{ ok, space, folder, prompt }` (makes the issue's space when it has none, once even when called twice at once), `/pickup {issue,item}` → `{ ok, id }` or `{ ok:false, needsForm:true }` when the issue has no folder yet. `/api/launch` accepts `issue: { issue, item }`: after a launch it calls `startItem` and keeps the folder and choices on the issue. `/api/space/goal {id, goal}`; `/api/space/create` takes `goal`. The snapshot gets `issues` (this workspace's list).
- Pick-up launch body: `{ prompt, cwd: folder, space, worktree: true, worktreeName: 'issue-<item>', name: <item text cut to 40 as a name>, ...choices }`.
- Linking a session: in the same pass that claims spaces, `claimItem(ws, launchId, sessionId)` for sessions launched with that id.
- Branches: on each roster pass, for a working item with a session whose branch is not its repository's default, `addBranch`.
- Done: on GitHub's `onChange`, for each open item with branches, its repository's `mergedOf(slug)` holding one of them → `done(ws, issue, item, pr)` and broadcast. `targets()` also returns each open item's branches (`{ sessionId: 'item:<id>', ws, common, branch }`, `common` from its folder) so the poller keeps following them after the agent is gone.
- Deleting a space calls `unlinkSpace`. Renaming an issue renames the space it owns, and its goal.
