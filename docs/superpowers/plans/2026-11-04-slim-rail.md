# Slim Rail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the rail's two-line tiles with 26 px one-line rows, nest each session's subagents under it as a small tree, and add keyboard navigation and a name filter.

**Architecture:** All in `public/index.html`. `tile()` becomes a row builder (`srow`) that also owns the session's subagent rows; `renderBoard()` places session rows and, when a tree is open, their subagent rows, in each section body. A small `trees` state (per session: `auto | open | shut`, hover flag, fold timer) decides unfolding. A rail key handler on `document` moves `open` through the rows in visual order; a find input filters by name. The drawer gains a `subFocus` highlight.

**Tech Stack:** Vanilla browser JS and CSS, one HTML file, no build. Verification by `node --check`, headless Chrome, a synthetic-hook scenario script.

**Spec:** `docs/superpowers/specs/2026-11-04-slim-rail-design.md`

## Global Constraints

- `public/index.html` stays one file; no dependencies; existing tokens and helpers (`el`, `setText`, `setAttr`, `patch`, `ago`, `confirmOr`, `armed`, `HINT`, `stateOf`, `subState`, `asking`, `reqsOf`, `askText`, `summary`, `label`) are reused, not duplicated.
- Row height 26 px (session), 24 px (subagent), section header 28 px; names 13 px weight 500; details 11.5 px mono; all rail text other than names uses `--fg-dim`; the hover action button stays 22 px.
- State colours unchanged: waiting `--amber`, busy `--run`, idle `--idle-body`, finished `--ok`, failed and stopping `--stop`.
- Shortcuts never fire when `dlg.open`, inside `textarea, input, select, [contenteditable], [role=menu], [role=separator]`, or with a modifier other than Shift; arrows only with focus on `body` or inside `#board`.
- Automatic tree changes are deferred while the pointer is over that session's rows; manual ones are immediate.
- Rail default width 260 px, drag bounds 220 to 560.

## Review Focus

1. A session with 20 subagents: the tree must not push every other section off screen; rows stay 24 px and the section body scrolls as today. (Task 2: scenario with 20 `SubagentStart`s.)
2. Holding ↓ across 13 sessions: one follow per step, debounced 120 ms, the drawer ends on the last row and the rail has scrolled it into view. (Task 3: scenario asserts `scrollIntoView` was reached via `getBoundingClientRect` within the board.)
3. A Needs-you row whose ask comes from a subagent: the row says `sub:Bash`, the subagent row says `asks you` in amber, and `n` lands on that session. (Task 2 and 3 scenario.)
4. The find field with a query that matches nothing: every section shows its header with `0/N`, the drawer keeps the open session, Esc restores everything. (Task 3.)
5. A section folded (Idle, Finished by default): ↑/↓ skip its rows; unfolding it mid-navigation includes them on the next key. (Task 3.)

### Task 2: Subagent trees

**Files:**

**Interfaces:**
- Produces: `trees: Map<sessionId, { mode: 'auto'|'open'|'shut', hover: boolean, pending: boolean|null, timer: number|null, known: Set<agentId> }>`; `treeOpen(s): boolean` (the effective state after the rules); `setTree(s, open: boolean)` (manual); `subRow(s, a): HTMLElement` (`button.sub[data-state]`, children `span.sd` square, `span.sn` title, `span.sage`); `subFocus: string|null` (agent id) and `focusSub(s, a)` (sets `open`, `subFocus`, unfolds `d-side` if `sideFolded`, `render()`, scrolls the details row into view).

- [ ] **Step 1: CSS.** `.sub{display:flex;align-items:center;gap:7px;height:24px;padding:0 8px 0 24px;border:0;border-radius:5px;background:none;width:100%;text-align:left;cursor:pointer;position:relative;color:var(--fg-dim);font-size:12px;white-space:nowrap}` with `::before` (vertical hairline at left 11 px, `--line-strong`) and `::after` (7 px horizontal tick at 12 px down); `.sub:hover{background:var(--hover)}`; `.sub.focus{box-shadow:inset 0 0 0 1px var(--fg)}`; `.sd{width:5px;height:5px;border-radius:1px}`; `.sage{margin-left:auto;font:11.5px var(--mono);color:var(--fg-dim)}`; `.sub[data-state="waiting"] .sage{color:var(--amber)}`; `.chev-slot svg{width:10px;height:10px;fill:none;stroke:currentColor;stroke-width:1.8;stroke-linecap:round;stroke-linejoin:round;transition:transform .12s}`; `.chev-slot.open svg{transform:rotate(90deg)}`.
- [ ] **Step 2: Tree state.** `treeOpen(s)`: `t = trees.get(id)` (create with `mode:'auto'`); if any `a.agentId` not in `t.known`: `t.known` ← all ids, `t.mode = 'auto'`, clear timer. `live = s.subagents.some(a => ['running','waiting'].includes(subState(s,a)))`. ### Task 3: Keys and find

**Files:**
- Modify: `public/index.html` global keydown (~2204), `render()` (follow debounce), `renderBoard` (filter and counts), new `#rail-find` input and `#rail-keys` strip in the board markup, CSS.

**Interfaces:**
- Produces: `railRows(): Array<{ kind: 'session'|'sub', s, a? }>` in visual order over unfolded sections and open trees, filtered by `railQuery`; `moveSel(delta: 1|-1)`; `nextNeedsYou()`; `railQuery: string`; `showFind(on: boolean)`.

- [ ] **Step 1: Markup and CSS.** Inside `nav#board`, first child `input#rail-find[type=search][placeholder="Find a session"][hidden]` (26 px, `--mono` 12 px, same `.field` look), last child `div#rail-keys` with four `kbd` groups per spec, 11 px `--fg-dim`, hidden when `board.clientWidth < 240` (set in the `r-grip` resize callback and on load).
- [ ] **Step 2: Filter.** `railQuery` lower-cased; in `renderBoard`, `list` becomes `list.filter((s) => !railQuery || label(s).toLowerCase().includes(railQuery))` for placement; the count shows `${shown}/${total}` when filtering, else `total`; a section with zero matches shows only its header.
- [ ] **Step 3: Key handler.** New `document.addEventListener('keydown', railKeys)` before the Escape handler: guard per Global Constraints; `ArrowDown/ArrowUp` → `moveSel(±1)` and `preventDefault`; `ArrowRight/ArrowLeft` → `setTree(sessionOf(open), key === 'ArrowRight')` when it has subagents; `n` → `nextNeedsYou()`; `/` → `showFind(true)` and focus the field; `Escape` when the field has focus or `railQuery` → `railQuery = ''`, `showFind(false)`, render (and stop there; the existing Escape handler runs only when nothing was cleared).
- [ ] **Step 4: `moveSel`.** Rows from `railRows()`; current index = the row matching `open` and `subFocus` (sub rows) or `open` (session rows), else −1 → first row; target row: session → `cancelAdvance(); open = s.sessionId; subFocus = null; render()`; sub → `focusSub(s, a)`; then `t.btn.scrollIntoView({ block: 'nearest' })`. `followOpen` call in `render()` is debounced 120 ms (`clearTimeout(followTimer); followTimer = setTimeout(() => followOpen(open), 120)`), with an immediate call when `open` changed by click (pass a flag).
- [ ] **Step 5: `nextNeedsYou`.** `ids = asking().filter(matches query)`; `i = ids.indexOf(open)`; `open = ids[(i + 1) % ids.length]` if any; render.
- [ ] **Step 6: Scenario additions.** The headless DOM dump cannot dispatch keys, so the scenario checks shape only: `#rail-find` hidden by default, `#rail-keys` present with four `kbd` groups. Key behaviour is verified by hand in Step 7.
- [ ] **Step 7: Hand check** on the throwaway server in a real browser: ↑/↓ across sections including into a tree; → / ←; `n`; `/` + Esc; keys silent in the reply box, the launcher and the theme menu; grips still resize with arrows.
